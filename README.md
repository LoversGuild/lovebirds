# Lovebirds

Lovebirds is a library and command-line tool for managing event and participation information in [The Lovers’ Guild][guild].

This package is currently used internally, but documentation is minimal due to anticipated changes to these tools in the near future.

If you find this tool useful, let us know at [The Lovers’ Guild][guild].

[guild]: https://loversguild.org/

## Installation

This package utilizes the Python packaging tool `poetry` for project setup.  
`poetry` can be installed using a distribution's package manager, `pipx`, or another method for installing *PyPi* packages.

After installing `poetry`, run:

```sh
$ poetry install
```

This command will install the `lovebird` script and its dependencies into a virtual environment.

## Using the `lovebird` Command-Line Tool

Currently, invoking `lovebird` (the command-line tool) can be complex, as a significant amount of configuration information must be passed through command-line options.

`lovebird` has hierarchical subcommands.  
Options for a subcommand must follow the subcommand's name to be recognized.

The `-p` or `--people=` option must always be included, indicating the location of the Lovers database file.

For many commands, the `--event=` option is necessary, specifying the event ID for which `lovebird` will work with data.

To send messages, the event configuration file should be passed using the `--event-file=` option.

The `--operator=` option specifies the ID of the person making changes to the database or sending messages.  
This person ID must be present in the Lovers database and is recorded as the operator of actions performed by `lovebird`.

The `--log-level=` option enables adjustment of the log level, making `lovebird` more verbose or quiet as needed.

The `--dry-run` option is applicable for all commands, allowing for a test run without making actual changes or sending messages.

### Examples of Invoking `lovebird`

#### Inviting People to a New Event

```sh
$ poetry run lovebird -p <path/to/lovers.yaml> phase -e <new-event-id> add -x True -o <operator-id> -S organizer -s invited -r participant
```

This command adds a new participation phase for every person in the database, marking everyone as an invited participant in the specified event.

#### Sending Messages

```sh
$ poetry run lovebird -p <path/to/lovers.yaml> send -e <path/to/event.yaml> -o <operator-id> --fcc=<path/to/fcc/maildir> <message-name>
```

This command reads the event configuration file, generates messages according to the templates, and sends the specified message to all relevant recipients.

#### Importing Encrypted Registrations

```sh
$ poetry run lovebird -p <path/to/lovers.yaml> register -o <operator-id> <paths/to/registrations.json.gpg>
```

This command imports registration information from supplied encrypted files generated by `lentopusu`.  
Each registration is processed only once, even if this command is executed multiple times with the same input files.

This is an interactive process.
It will prompt several questions, and allows registrations to be amended for correcting errors made by individuals entering their details.

#### Listing Participants

```sh
$ poetry run lovebird -p <path/to/lovers.yaml> list -e <event-id> -f 'phase is defined and status == "signed"' full_name role birth_year
```

This command lists the full name, participation role, and birth year of every person who has signed into the event defined by `<event-id>`.

## Hacking

The Python source code is located in the `src/` directory, which contains several subdirectories:

- `cli/`
: Defines the command-line interface.

- `models/`
: Contains Python dataclasses for data models.

- `templates/`
: Holds low-level template evaluation routines.

The code responsible for template management is in need of revising, which will also necessitate revisions to the code for the `list` and `phase` subcommands.
